Design alignment summary
- The project now matches the high-level DESIGN.md structure:
  - P1 / P2 / P3 queue separation exists.
  - StartTask / ResetTask / ExitTask exist.
  - CameraTask / MicrophoneTask / BatchParticleExecutionTask exist as resident runtime tasks.
  - GenerateParticleTask creates P3 particle tasks.
  - BreezeTask exists as a fallback P2 task with fixed-power particle generation.
  - ChangeDandelionTask exists as a P2 task that rebuilds the dandelion cluster.
  - SingleParticleTask is resumable and writes through the ordered shared-state path.
  - RenderData remains task-owned for writes and renderer-owned for reads.
- The main remaining gap is behavioral rather than structural:
  - CameraTask now enforces bridge sample freshness / staleness handling, but still needs tuning against real live camera behavior and mouth-state thresholds
  - MicrophoneTask now supports native C++ capture and JSON/offline bridge input, and consumes each bridge sample once, but breath / voiced / silence classification is still heuristic
  - BatchParticleExecutionTask now drives world decay and cleanup, but still does a simplified world tick compared with full DESIGN.md timing semantics
  - resident task yielding now allows pending P3 work to drain with single-thread alternation, multi-thread resident/P3 sharing, and same-frame tie-break selection, but the exact fairness policy is still simpler than full DESIGN.md RR semantics
  - SDL visualization now reflects the layer split much more clearly, but the camera layer still shows a bridge-status viewport rather than a real embedded camera frame texture
